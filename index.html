More unlearning seeds are not enough

Repeating unlearning on one trained model does not reveal how the outcome changes when the original model is trained again. When training contributes to variability, additional unlearning runs cannot generally replace independent training runs. Lanyon et al. explain why and give guidance on allocating compute between training and unlearning repetitions.

SUPREME supports the nested design needed to investigate these sources: I trained models → J unlearning repetitions per model → K evaluation repetitions per unlearned model. Separate stage seeds support the analysis; GPU and cluster execution support the repeated workload.

The framework provides this experiment structure, not an automatic variance-component report. The Pins results below use matched stage seeds and show combined variation. Read the variance formula, seed controls and interpretation limits →

Abstract

Machine unlearning removes the influence of specific training data from a trained model without retraining it from scratch. Evaluating an unlearning method requires repeating training, unlearning, and evaluation across multiple seeds, which is computationally expensive. To our knowledge, existing image classification unlearning frameworks run on a single GPU, which limits how many seeds can be evaluated in reasonable time.

We introduce SUPREME, an open-source framework that distributes these stages across multiple GPUs. SUPREME makes three contributions: a registry-based design for adding new methods, metrics, models, and scenarios; a multi-GPU architecture supporting multiple accelerators and precision modes; and a demonstration on Pins Face Recognition using ResNet18 and ViT under full-class and random-sample unlearning across ten seeds. The framework is available at github.com/pedroandreou/supreme-unlearning.

Key Contributions

  Extensible framework

Registry-based design covers datasets, model architectures, unlearning methods, evaluation metrics, and unlearning scenarios. New components are added by implementing an interface and registering a module path, with no framework changes required.

  Multi-GPU support

Hardware-agnostic architecture built on PyTorch and Lightning Fabric, with DDP, FSDP, and DeepSpeed ZeRO-1/2/3 distribution applied to training, unlearning, and evaluation. To our knowledge the first image classification unlearning framework to do so.

  Demonstration

The paper reports Pins Face Recognition experiments with ResNet18 and ViT, full-class and random-sample unlearning, across ten seeds on one GPU. Several configurations show substantial variation across seeds.

The pipeline

SUPREME runs a three-stage pipeline with separately configurable seeds, supporting nested experiments that investigate variation at each stage:

  1. Stage 1, Training. Train the original model Mo on the full dataset D using training seed st.
  2. Stage 2, Unlearning. For each forget target c ∈ C, train the retrained baseline Mr from scratch on the retain set Dr using unlearning seed su. Then for each method a ∈ A, apply a to Mo to obtain the unlearned model Mu.
  3. Stage 3, Evaluation. Evaluate Mu against Mr on the test forget and retain sets using evaluation seed se, computing the configured metrics in E.

Methods share the seed configuration and original model for a given run. The retrained baseline Mr is produced once per (st, j, c) and shared across methods. The matched protocol used in the paper combines the sources of randomness; separate stage seeds support further investigation.

Demonstration on Pins Face Recognition

We demonstrate SUPREME on Pins Face Recognition, an image classification benchmark of 17,534 facial images across 105 celebrity identities. Two scenarios are evaluated:

  • Full-class unlearning removes all samples for five identities: alex_lawther, bill_gates, danielle_panabaker, hugh_jackman, josh_radnor.
  • Random-sample unlearning removes a 0.1% subset of training samples drawn from across all classes.

Both architectures (ResNet18 and ViT) are evaluated across I = 10 training seeds (260–269) on a single NVIDIA L40S GPU to maintain exact numerical parity with the reference implementations.
